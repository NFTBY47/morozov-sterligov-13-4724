# Clearing: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

Clearing объединяет завершённые успешные покупки в пакеты. Повторного списания денег здесь нет.

`ClearingTransaction(transaction_id, merchant_id, amount: Money, status)` — готовая неизменяемая операция с положительной суммой и статусом `APPROVED` или `DECLINED`.

| Объект или метод | Назначение |
|---|---|
| `ClearingBatch(batch_id, currency)` | Создаёт пакет в состоянии `OPEN`. |
| `transactions` | Возвращает состав пакета как `tuple`. |
| `add_transaction(tx)` | Добавляет подходящую операцию в пакет. |
| `total() -> Money` | Возвращает сумму операций в валюте пакета. |
| `close()` | Переводит непустой пакет в `CLOSED`. Повторное закрытие вызывает `INVALID_STATE`. |

Добавление допустимо, только если пакет открыт, операция успешна, её валюта совпадает с валютой пакета и её ID ещё не присутствует. `ClearingService` дополнительно проверяет, что `transaction_id` не включён в другой его пакет — открытый или закрытый. Для этого предоставлена проверка по фактическому составу пакетов; внешнего флага `already_cleared` недостаточно. Неуспешное добавление не должно занимать ID.

Методы сервиса `create_batch(batch_id, currency)`, `add(batch_id, tx)`, `close(batch_id)` и `get_batch(batch_id)` возвращают неизменяемый `BatchSnapshot`, а не внутренний изменяемый пакет. Его поля: `batch_id`, `currency`, `status`, `transactions`, `total`.

Общий интерфейс дополнительных ограничений — `ClearingEligibilityRule.check(batch, tx) -> CheckResult`. `MaximumBatchCountRule(maximum)` ограничивает число операций, `MaximumBatchAmountRule(maximum: Money)` — их сумму. Эти правила не заменяют обязательные проверки статуса, валюты и повторов. Одновременная работа нескольких потоков не рассматривается.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

`ClearingBatch` принимает `batch_id` и код валюты позиционно.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
